# 邻传

本目录是独立的鸿蒙工程根目录，请在 DevEco Studio 中打开本目录。Windows 客户端的设计位于 `../windows/README.md`。

鸿蒙原生局域网文件传输工具。当前实现重点是移动端的系统分享入口、附近设备选择、接收确认和设备可见性。

## 已实现

- 相册、文件管理等应用通过系统分享菜单发送文件到 邻传；覆盖冷启动和热启动。
- 打开应用后可响应局域网内的发现请求。点「搜索附近设备」、选好待发送文件或打开系统分享窗口时，才主动搜索一轮。
- 主页右上角的时钟和齿轮图标分别打开传输记录与设置。左右滑动传输记录可删除单条记录。
- 「连接过的设备」上方可直接生成临时分享链接。未选文件时，选完即生成。顶部「活动」图标会在有传输或有效链接时出现，可单独停止传输、复制链接或让链接失效。
- 同时支持向最多 4 台不同设备发送文件，以及保留最多 10 条临时分享链接。每一项使用创建时选中的文件。
- 主页的「所有人可见」开关打开后持续 10 分钟，到期或提前关掉后恢复为「仅连接过的设备」。
- 「设置 → 局域网服务」可暂停或启动发现和收发。暂停会中断传输并关闭临时分享链接。
- 保存实际到期时间，应用重启不延长开放窗口；每次网络授权重新判断有效期。
- 接收方确认有效传输会话后保存连接记录；发现和注册不会自动创建连接记录。
- 发送页将「连接过的设备」和「未连接过的设备」分组显示。离线设备默认折叠。左右滑动已连接设备可删除记录，也可开启或关闭自动接收。删除会撤销后续发现和连接的认证资格。
- 邻传 设备之间使用带用途、接收方、时间戳与随机数的 HMAC-SHA256 认证进行定向发现；防止仅伪造指纹或重放发现消息。
- 接收前确认、发送取消、按完成文件数量显示进度；活跃传输申请系统 dataTransfer 长时任务。
- 保留初始 LocalSend v2 HTTP 传输及临时网页下载原型。

## 使用流程

首次连接时，接收方打开“所有人可见 · 10 分钟”。发送方可以保持“仅连接过的设备”，仍能发现接收方并发起发送。对方确认后保存连接记录。窗口到期后，两端通过已保存地址和独立连接凭据定向发现。

从图库或文件管理的系统分享菜单选择 邻传 后，会打开临时分享窗口。窗口自动搜索附近设备，点击设备旁的「发送」即可传输。本次选中的文件独立于主界面的文件清单。接收 邻传 设备发来的文件时，可选择「接收并允许以后自动接收」，并在「连接过的设备」关闭。

删除记录保留历史文件，并影响后续连接；已经确认的传输会话允许继续完成。开放窗口内，被删除的设备可以作为新设备申请连接，仍需本机确认。

## 当前边界

- 尚未接入华为分享私有协议、系统设备列表或原生接收弹窗。
- 在「设置」中可选择跟随系统、浅色或深色。图库分享窗口沿用同一项外观设置。
- 在「设置 → 传输通知」允许通知后，服务仍在运行时，后台接收请求可通过通知返回邻传确认，发送和接收完成也会提示。主应用的发送和已确认接收使用系统数据传输任务，接收实况窗显示文件接收进度。应用被系统挂起或终止时，局域网请求无法唤醒应用。图库临时分享窗口的直接发送需要保持窗口打开。
- 鸿蒙电脑可在系统设置的「应用和元服务 → 应用启动管理」添加邻传。手机和平板的应用启动由系统管理。
- 目前使用 HTTP，配对凭据初次交换也经 HTTP，不能抵抗同网窃听和中间人。HMAC 不能替代 TLS。正式发布前需要补齐 TLS 与证书身份验证。
- LocalSend 标准客户端没有 邻传 的连接认证扩展，因此即使留有连接记录，仍需在“所有人可见”窗口内连接；不能把可伪造的 HTTP 指纹当作认证。HTTPS LocalSend 设备暂不支持发送。
- 每次最多 20 个文件。发送、接收和临时链接下载都按块读写，文件大小取决于文件系统与可用空间。当前版本尚未实现断点续传。
- 接收文件保存在应用私有 `received` 目录，导出至用户目录和完成后打开文件尚待实现。
- 临时网页目前只提供下载，上传和二维码不在本次实现范围。

## 真机验收清单

1. 相册多选和文件管理多选分别分享至 邻传，冷启动、热启动均正确替换清单。
2. 新安装默认仅连接过的设备，陌生设备不能发现本机信息或发起接收确认。
3. 仅接收方临时开启可见时，发送方能发现并发送，接收方看不到尚未连接的发送设备。10 分钟到期、提前结束和重启后按原截止时间收回接收权限。
4. 双方确认连接后，均切换至仅连接过的设备，仍能互相发现并发送。
5. 删除记录后，对方不能在受限模式重新发现或连接；历史文件保留。
6. 拒绝、取消、中途断网、同名文件和校验失败行为符合提示。
7. 已确认传输切至后台或锁屏仍能完成，系统任务在完成或取消后结束。
